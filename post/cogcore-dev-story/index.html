CogCore：从一篇论文到可运行的认知内核

2026-06-05 • 4 分钟阅读 • CogCore · AI · Agent · 认知架构 · Python

起源：LLM 缺的那块拼图

2025-2026 年，AI Agent 框架遍地开花。LangGraph、CrewAI、AutoGen……每个都在解决同一个问题：让 LLM 能多步推理、调用工具、完成任务。

但用了一段时间后，我发现一个更深层的空缺——长期连续性。

Agent 框架的核心模式是 ReAct 循环（思考→行动→观察→再思考），每次循环都从零开始构建上下文。它记不住上一轮的"认知状态"：哪些信息是确定的、哪些是猜测的、哪些行动成功了、系统当前是疲劳还是警觉。

LLM 擅长即兴生成，但不擅长持续维护一个内部状态。

这篇论文《人工心智架构》（Artificial PsyArch, AP, 2026）正好切中这个问题。它不是教你如何写 prompt，而是给出了一套可复现的认知闭环设计：状态池、联想记忆、内源感受、情绪调制、行动驱动力。

我花了一个月时间，把它从论文变成了一个可运行的 Python 项目——CogCore。

先看结果

架构：三个关键设计

1. 状态池 + 能量 = 认知货币

传统 Agent 把记忆存进向量数据库，每次查询算相似度。CogCore 用状态池，每个认知对象都带着能量。

实能量 = 外部证据的强度；虚能量 = 内部预测的强度；认知压 = 两者的差值——现实与预期的张力。

这个设计来自论文的一个洞察：记忆不应该只看"像不像"，还要看"重不重要"。能量会随时间衰减，被注意力选中的会增强，未被引用的会逐渐消亡。这不是一个只增不删的数据库，而是一个动态场。

2. HDB：理解和学习发生在同一路径

传统系统把"理解输入"和"记住知识"分成两步。CogCore 的 HDB（查存一体模块）在匹配已有结构的同时，把未匹配的部分作为残差写入。读就是写，理解就是学习。

2-gram tokenization + Jaccard 匹配 + 残差驱动的子结构生长。当我说"今天天气真好"，系统不是把它存成一条记录，而是沿着已有的"天气"结构向下生长一个新分支。

3. CFS + NT：认知有情绪

CFS（认知感受系统）产生五种信号：违和感、正确感、期待、压力、疲劳。NT（情绪递质）有六个通道：专注、觉醒、谨慎、探索、疲劳、稳定。

它们不参与语义理解，但参与参数调制：违和感高会导致行动阈值提高，让系统更谨慎；连续失败会让疲劳累积，减少注意预算；正反馈会增强探索倾向。

开发历程：三个阶段的取舍

M0：把论文的公式变成代码

最直接的挑战：论文有公式（NT(t+1) = baseline + inertia * (NT(t) - baseline) + impulse），但代码要处理的是状态合并。

用 LangGraph 的 StateGraph 作为图引擎，每个 stage 返回一个 patch，由 Reducer 机制自动合并。这里踩了一个坑：返回 partial dict 会覆盖嵌套对象。修复方案是用 Pydantic + StateUpdater 链式模式。

另一个教训：测试先行。M0.1 骨架只有 5 个测试，到 M0.4 涨到 127 个。没有测试的话，集成时的数据丢失和双重累加陷阱每一个都会让你 debug 半天。

M1：从内核到对话

最难的部分不是写 LLMBridge，而是设计配置系统。OpenAI 兼容协议意味着同一份代码要能连 Ollama、OpenAI、vLLM。最终方案：config.toml + Pydantic 校验 + 环境变量覆盖。

持久化选择了 SQLite 而非 Postgres。不是因为 Postgres 不好，而是零 Docker 依赖对于本地优先的项目更重要。

M2：持续认知服务

从"每次手动调 invoke"变成"一直在后台跑"的转换，核心是 CogCoreService。它管理 tick 计数、调度自动 tick、处理输入队列、自动写日记。

旁路开关（enabled flag）是消融实验的关键基础设施。没有它，E19/E20 实验无法隔离变量。

数据与验证

论文 E01-E17 + 新增 E18-E20 = 20 项实验全部通过。

最有说服力的是 E13：在 48 个对照 case 上，CogCore 的上下文投影平均包含 7.75 个可审计字段（情绪递质、能量状态、记忆来源等），而朴素 RAG 只有 1.25。而且 RAG 有 25% 的概率把冲突的旧数据当作正确答案。

一些工程决策

为什么不用 Postgres？ 在 Windows 上搞 Docker 太折腾了。SQLite 覆盖 90% 的单机场景。

为什么不用 OpenAI Agents SDK？ 它解决的是 Agent 编排，我们自己就在写 Agent 编排——CogCore 的 10-stage tick 流水线就是编排器。我们只需要 OpenAI SDK（底层 API 调用），不需要上层的 Agent 框架。

为什么 TOML 做配置？ Python 3.11+ 内置 tomllib，零依赖。比 YAML 安全，比 JSON 可读。
